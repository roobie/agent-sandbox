## Directory Purposes

**`images/`:**
- Purpose: Source code for Docker images used in sandboxes
- Contains: Dockerfiles, build scripts, firewall initialization code, policy files
- Key files: `images/build.py` (orchestrator), `images/base/init-firewall.py` (core logic)

**`images/base/`:**
- Purpose: Foundation layer shared by all agents
- Contains: Debian base setup, system dependencies, firewall infrastructure
- Key files:
  - `Dockerfile` - Base image definition (Debian + dev tools + iptables)
  - `entrypoint.sh` - Container startup (firewall init + UID/GID adjustment)
  - `init-firewall.py` - Firewall initialization script (iptables/ipset)
  - `policy.json` - Default policy (GitHub only)

**`images/agents/claude/` and `images/agents/copilot/`:**
- Purpose: Agent-specific customizations
- Contains: Claude Code installation (via mise), shell aliases, agent-specific policies
- Key files:
  - `Dockerfile` - Extends base with agent CLI and aliases
  - `policy.json` - Extended policy with Claude Code API endpoints (api.anthropic.com, sentry.io, etc.)

**`.devcontainer/`:**
- Purpose: VS Code Devcontainer configuration for developing agent-sandbox itself
- Contains: VS Code-specific entrypoint and settings
- Key files:
  - `Dockerfile` - Extends Claude agent, overrides policy with VS Code domains
  - `devcontainer.json` - VS Code configuration (runArgs, mounts, postStartCommand)
  - `policy.json` - Extended policy including VS Code marketplace and update domains

**`devcontainer/templates/minimal/claude/`:**
- Purpose: Reusable template for other projects
- Contains: Minimal Compose and Devcontainer setup, copy these files to your project
- Key files:
  - `.devcontainer/` - Ready-to-use VS Code config
  - `docker-compose.yml` - Ready-to-use Compose config
  - `README.md` - User-facing instructions

**`docs/`:**
- Purpose: Project documentation
- Contains: Roadmap, milestone tracking, policy examples
- Key files:
  - `docs/plan/project.md` - Roadmap and release notes
  - `docs/plan/milestones/` - Per-milestone tasks
  - `docs/policy/` - Policy file examples

**`.planning/codebase/`:**
- Purpose: GSD (Get Stuff Done) codebase analysis documents
- Contains: Auto-generated architecture and structure documentation
- Generated by: `/gsd:map-codebase` command
- Consumed by: `/gsd:plan-phase` and `/gsd:execute-phase` commands

## Key File Locations

**Entry Points:**
- `images/build.py` - Orchestrates building all images locally
- `docker-compose.yml` - Starts agent sandbox in Compose mode (project root)
- `.devcontainer/devcontainer.json` - Entry point for VS Code Devcontainer

**Core Logic:**
- `images/base/init-firewall.py` - Firewall initialization (network restriction enforcement)
- `images/base/entrypoint.sh` - Container startup and privilege escalation management

**Configuration:**
- `images/base/policy.json` - Base policy (GitHub)
- `images/agents/claude/policy.json` - Claude policy (GitHub + Claude Code APIs)
- `.devcontainer/policy.json` - Development policy (GitHub + Claude Code + VS Code)

**Templates for Users:**
- `devcontainer/templates/minimal/claude/.devcontainer/` - Copy to your project
- `devcontainer/templates/minimal/claude/docker-compose.yml` - Copy to your project

## Naming Conventions

**Files:**
- Python scripts: `lowercase_with_underscores.py` (e.g., `build.py`, `init-firewall.py`)
- Shell scripts: `lowercase_with_hyphens.sh` (e.g., `entrypoint.sh`)
- Configuration: `lowercase.json` or `lowercase.yaml` (e.g., `policy.json`, `devcontainer.json`)
- Images: Tag format `agent-sandbox-{agent}:local` for local builds, `ghcr.io/mattolson/agent-sandbox-{agent}:{version}` for published

**Directories:**
- Image directories: `images/{layer}/{agent}` (e.g., `images/agents/claude/`)
- Template directories: `devcontainer/templates/{style}/{agent}/` (e.g., `devcontainer/templates/minimal/claude/`)
- Milestone directories: `docs/plan/milestones/{milestone}/tasks/` (e.g., `docs/plan/milestones/m1-devcontainer-template/tasks/`)

**Docker Image Tags:**
- Local build: `agent-sandbox-{agent}:local` (e.g., `agent-sandbox-claude:local`)
- Published: `ghcr.io/mattolson/agent-sandbox-{agent}@sha256:{digest}` (pinned by digest for reproducibility)

## Where to Add New Code

**New Agent Support:**
- Create directory: `images/agents/{agent-name}/`
- Add files:
  - `Dockerfile` - Extends `agent-sandbox-base:local`, installs agent CLI
  - `policy.json` - List domains required by this agent
- Register in `images/build.py` - Add `build_{agent-name}()` function following pattern of `build_claude()`
- Update main() in `images/build.py` to call new builder function

**New Firewall Feature:**
- Edit: `images/base/init-firewall.py`
- Add function following existing patterns:
  - Helper functions should validate inputs (e.g., `validate_ipv4()`, `validate_cidr()`)
  - Processing functions should be idempotent
  - Errors should raise `FirewallError` with clear messages
  - Main entry point should call functions in strict order

**New Policy Domain:**
- Edit policy file:
  - Base policy: `images/base/policy.json`
  - Or agent-specific: `images/agents/{agent}/policy.json`
  - Or development: `.devcontainer/policy.json`
- Add domain to `domains` array (DNS name will be resolved at startup)
- Or add service to `services` array if using dynamic IP fetching (only "github" supported currently)

**New Documentation:**
- User-facing: Add to `README.md`
- Troubleshooting: Add to `devcontainer/templates/minimal/claude/README.md`
- Planning: Add to `docs/plan/` with milestone tracking

**Customization for Other Projects:**
- Copy template: `devcontainer/templates/minimal/claude/.devcontainer/` → `your-project/.devcontainer/`
- Or copy Compose: `devcontainer/templates/minimal/claude/docker-compose.yml` → `your-project/`
- Edit policy file in copied location (`your-project/.devcontainer/policy.json` or `your-project/.env.compose`)
- Build or pull images as needed

## Special Directories

**`.git/`:**
- Purpose: Version control repository
- Generated: Yes (git init)
- Committed: Yes (tracked with .gitignore)

**`.ruff_cache/` and `.serena/`:**
- Purpose: Tool-specific caches
- Generated: Yes (runtime)
- Committed: No (.gitignore)

**`node_modules/` (if present):**
- Purpose: Node package cache (not currently used)
- Generated: Yes (npm install)
- Committed: No (.gitignore)

**Docker volumes (named, not in directory):**
- `claude-state` - Claude Code credentials and config (persists across rebuilds)
- `command-history` - Shell history (persists across rebuilds)
- `mise-state` - Tool version manager state
- `cargo-state` - Rust toolchain cache
- `local-bin-state` - Local binary installations

## Relationship Between Modes

**Compose Mode:**
- Uses: `docker-compose.yml` (project root)
- Loads image: `agent-sandbox-claude:local` (must be built first via `images/build.py`)
- Mounts workspace: cwd → `/workspace`
- Mounts volumes: Named volumes for credentials, history, cache
- Entrypoint: `images/base/entrypoint.sh` (initializes firewall, drops to dev user)
- Shutdown: `docker compose down`

**Devcontainer Mode:**
- Uses: `.devcontainer/devcontainer.json` + `.devcontainer/Dockerfile`
- Builds image: Extends `agent-sandbox-claude:local` with VS Code policy
- Orchestrated by: VS Code Dev Containers extension
- Entrypoint: VS Code bypasses shell entrypoint, runs postStartCommand instead
- postStartCommand: `sudo /usr/local/bin/init-firewall.py` (firewall init only)
- Shutdown: VS Code Reopen Locally command

**Template Mode (for other projects):**
- Copy: `devcontainer/templates/minimal/claude/` contents to your project
- Images: Pulled from GHCR by default, or use local builds (edit references)
- Policy customization: Edit `.devcontainer/policy.json` or `~/.config/agent-sandbox/policy.json`
- Uses: Identical architecture, just deployed to a different repo
