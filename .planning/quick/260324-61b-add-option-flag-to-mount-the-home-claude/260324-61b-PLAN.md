(CLAUDE.md, settings.json, etc.) without being able to modify it.

<task type="auto">
  <name>Task 1: Add --claude-config flag to sandbox:run</name>
  <files>mise.toml</files>
  <action>
Add a new boolean flag to the sandbox:run task's usage block:

```
flag "--claude-config -c" help="Mount host ~/.claude readonly into container at /home/dev/.host-claude"
```

In the run script, after the existing variable assignments and before the `docker run -d -i`
command, add a conditional block:

```bash
CLAUDE_MOUNT=""
if [ -n "${usage_claude_config:-}" ]; then
  HOST_CLAUDE="${HOME}/.claude"
  if [ -d "$HOST_CLAUDE" ]; then
    CLAUDE_MOUNT="--volume ${HOST_CLAUDE}:/home/dev/.host-claude:ro"
  else
    echo "Warning: ${HOST_CLAUDE} not found, skipping claude config mount"
  fi
fi
```

Then insert $CLAUDE_MOUNT into the docker run command, on a new line after the
go-cache volume line (before the --env lines). Since CLAUDE_MOUNT may be empty,
it will naturally be a no-op when the flag is not passed.

Mount target is /home/dev/.host-claude (NOT /home/dev/.claude which is already a
named volume for container-local claude state). This avoids volume conflicts.

Also update the docker-compose.yml commented-out section: replace the two individual
file mount lines with a single directory mount line as a reference example:

```yaml
      # Host Claude config (optional - uncomment to share host config readonly)
      # - ${HOME}/.claude:/home/dev/.host-claude:ro
```
  </action>

    - Flag present + ~/.claude missing: prints warning, continues without mount
    - docker-compose.yml comment updated to show directory mount pattern
  </done>
