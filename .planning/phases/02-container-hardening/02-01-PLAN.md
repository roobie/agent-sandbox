The current entrypoint.sh calls groupmod and usermod which write to /etc/group and /etc/passwd — both are image-layer files that become read-only under `read_only: true`. This causes the container to exit immediately at startup.

Fix: mount a tmpfs over /etc before running groupmod/usermod, so the writes land in memory rather than the read-only image layer. The tmpfs overlay approach copies the existing /etc contents to a tmpfs mount point and re-mounts it.

Replace the groupmod/usermod block with this pattern:

```bash
# Under read_only: true, /etc is part of the read-only image layer.
# groupmod and usermod write to /etc/passwd and /etc/group.
# Fix: copy /etc to a tmpfs overlay so writes succeed without touching the image layer.
# This must happen before any groupmod/usermod calls.
if [ "$(stat -f -c '%T' /etc 2>/dev/null || stat -c '%i' /etc 2>/dev/null)" ] && \
   ! (touch /etc/.rw-test 2>/dev/null && rm /etc/.rw-test 2>/dev/null); then
    # /etc is not writable — mount a tmpfs overlay
    mkdir -p /tmp/.etc-overlay
    cp -a /etc/. /tmp/.etc-overlay/
    mount --bind /tmp/.etc-overlay /etc
fi
```

Wait — `mount --bind` requires CAP_SYS_ADMIN which is dropped by cap_drop: ALL. This approach will not work.

Correct mitigation for Phase 2: Remove the UID/GID adjustment from entrypoint.sh. Accept fixed UID 500 for Phase 2. DEVENV-06 in Phase 3 will own the proper UID/GID adjustment solution.

The Phase 3 CONTEXT.md (DEVENV-06) is explicitly about "Non-root user execution (dev user) with UID/GID adjustment to match host workspace ownership". Phase 2 should not attempt to solve this.

**Actual fix:** Guard the groupmod/usermod calls so they are skipped when /etc is not writable (read-only rootfs). Log a warning instead of failing.

Replace the groupmod/usermod section in entrypoint.sh with:

```bash
# Under read_only: true, /etc/passwd and /etc/group are not writable.
# Skip UID/GID adjustment silently in that case — fixed UID 500 is used.
# Full UID/GID adjustment is a Phase 3 concern (DEVENV-06).
ETC_WRITABLE=true
if ! touch /etc/.rw-test 2>/dev/null; then
    ETC_WRITABLE=false
fi
rm -f /etc/.rw-test 2>/dev/null || true

if [ "$ETC_WRITABLE" = "true" ]; then
    # Adjust group if necessary
    if [ "$HOST_GID" != "0" ] && [ "$HOST_GID" != "$(id -g "$APP_USER")" ]; then
        if getent group "$HOST_GID" >/dev/null 2>&1; then
            APP_GROUP=$(getent group "$HOST_GID" | cut -d: -f1)
        else
            groupmod -g "$HOST_GID" "$APP_GROUP"
        fi
    fi

    # Adjust user UID
    if [ "$HOST_UID" != "0" ] && [ "$HOST_UID" != "$(id -u "$APP_USER")" ]; then
        usermod -u "$HOST_UID" -g "$HOST_GID" "$APP_USER"
    fi
else
    echo "entrypoint: /etc is read-only, skipping UID/GID adjustment (using fixed UID 500)" >&2
fi
```

This preserves the adjustment when /etc IS writable (dev mode without read_only), and gracefully skips it when read_only is active.
